# Phase 7: immutable world and coordinate foundation

`tools/build_migration_foundation.py` packages the existing phase 4 portable data and phase 5 world export for Unity. It does not regenerate maps, execute the archived GDScript, reinterpret saved identities, open personal saves, or modify the Godot game.

The 221 frozen JSON source documents comprise the world index, 162 map snapshots, shared tile definitions, the portable manifest and its 55 documents, and phase 5 runtime identities. Together they contain **335,783,962 bytes** in their committed LF text form; deterministic gzip stores these as **6,864,062 bytes**. Compression retains every source byte. Windows CRLF checkout endings are normalized back to the already hashed Git LF form before validation, as in the preceding migration phases. The original files remain in the repository.

`manifest.json` binds each compressed Unity resource to both its compressed SHA-256/length and its uncompressed source SHA-256/length. Gzip headers have a fixed timestamp and OS marker. The package also carries the state recorder's plain `state-oracle.json`, copied **byte for byte**, separately from those 221 documents. Its source length and digest are recorded in `stateOracle`; it is not normalized or reserialized. Only that exact oracle file and its generated `.meta` are accepted beside the exporter's other declared resources. An adjacent unknown file is rejected.

`--check` rebuilds the expected bytes in memory and verifies the owned output files and stable path-derived Unity GUIDs without repairing anything. `--write` validates all destinations before writing. Unknown files/directories, path traversal, noncanonical paths, symlinks/junctions, changed frozen anchors, duplicate source entries, malformed descriptors, duplicate JSON keys, and nonfinite JSON constants fail closed. The exporter owns `BlueMapFoundation/Resources/BlueMapFoundation` and its folder metadata; the C# `State` and `Session` folders have separate owners.

`FoundationWorldRepository` reads the package inside the native Unity player, verifies both hashes, enforces an exact expansion length of at most 128 MiB per document, and parses the retained typed values. It addresses all **37 maps**, **59 scenarios** and **162 recorded map/scenario snapshots**. The fresh world retains **49,758 terrain cells**, **640 tile definitions** and **980 structural object slots**: 905 original registry slots plus 75 appended resources, including 10 disabled slots. Disabled entries keep their place rather than shifting later identities.

Stable structural slot IDs have the namespace `map_object_slot`, the original map ID and original slot index. They coexist with the original `type:map:index` keys and the exact phase 5 custom runtime/save IDs; display labels never replace save IDs. Raw map, terrain, object, runtime and unknown future fields remain accessible as immutable typed source values. Signed 64-bit integers and IEEE double bit patterns, including negative zero, are retained. Unsupported typed Variant kinds are rejected rather than converted to strings or omitted. Recorded engine handles remain data contracts, not live Unity objects.

Loading is staged: a complete snapshot is validated before `Current` can change. Merely reading another map does not switch the session, and a failed lookup or parse preserves the current snapshot. These are the existing recorded projections, including progressed scenarios; phase 7 does not claim that later gameplay has already reproduced every recorded quest, crop or NPC update.

The coordinate adapter uses the existing **32 pixels per tile**. Godot pixel coordinates have downward Y; one Unity world unit represents one tile with upward Y. Points, top-left rectangles, sprite atlas rectangles, pivots and `Transform2D` matrices have explicit conversions. This avoids silently changing object feet, arrival points or map alignment when actual gameplay rendering is connected later.

Native collider helpers retain the source layer and mask bits and construct box, circle and polygon shapes. The player's reference foot collider remains a radius of 7 source pixels centered 8 pixels below the body origin. The adapter maps source single membership bits 0–22 to Unity layers 8–30 and reserves layer 31 for zero membership. It applies Godot's **either-body mask** rule per collider pair instead of Unity's different mutual filter semantics, and verifies real native contacts. It does not change project-wide physics settings. Multiple membership bits, unmapped bits and one-way tile effectors require explicit future adapters and currently reject; their full source descriptors remain preserved in the package.

The native check runner validates all 221 source documents, all 162 snapshots, map/terrain/slot counts and arrival round trips, plus staged loading, malformed values, numeric precision, decompression bounds, coordinate conversions and actual Unity physics contacts. Python fixture tests additionally exercise damaged sources and outputs, metadata damage, exact oracle copying, duplicate/path attacks, unknown extras and prevention of writes outside the owned folder. Engine proof belongs to the build's `FOUNDATION-CHECKS.json`; the Python package check alone does not claim to prove native execution.

This phase supplies the world, state and session foundations. Continuous player movement, full map decoration rendering, final camera/input behavior and the subsystem gameplay ports remain in their planned later phases. No extra world content or density is introduced here.
