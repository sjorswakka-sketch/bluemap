# Saved settings and legacy ConfigFile import

Phase 9 projects the original `settings.cfg`, `controls.cfg`, `meta.cfg`, and `ng_plus.cfg` into the isolated Unity profile. Importing never changes these original files. The store owns byte-for-byte archived copies, including comments, unknown sections, unknown fields, ordering, CRLF, and malformed documents. No personal files were opened while building or verifying this phase.

`SafeConfigDocument` parses bounded UTF-8 ConfigFile text as immutable data. Arrays, dictionaries, finite scalars, escaped strings, and multiline constructor records are supported. `Object(InputEventKey, ...)` and all other constructor records remain inert descriptions: there is no evaluation, reflection, resource loading, or object instantiation. Invalid UTF-8, excessive depth/items/length, and malformed syntax fail safely. A malformed settings document produces a visible diagnostic and safe defaults while its exact bytes remain available in the profile archive.

`LegacySettingsBundle.Decode` mirrors the source language precedence (supported saved locale, environment, system), audio values, achievement presence semantics, and New Game+ normalization. Source volume setters clamp playback to 0–1; imported finite values are also bounded for playback, with the original value preserved in the archived bytes. New Game+ uses the same frozen equipment, weapon, and experience registries as the save importer. No new achievements or progression rewards are granted by this import.

All 36 original input actions remain present, including 22 configurable gameplay actions and 14 fixed menu/aim actions. The original physical key fallback, modifiers, mouse buttons, controller buttons, axis directions, default deadzones, and deliberate empty/duplicate binding arrays survive. Invalid or oversized arrays retain defaults for the affected action. Missing legacy technique/garden shortcuts choose a free source candidate; when every candidate is occupied, the original deliberately empty result is retained. Interactive rebind conflict swapping remains separate from import: it cannot silently rewrite old duplicate bindings. Source-only hardware inputs without a Unity counterpart remain inert and retain their source description; their original bytes remain available for later support.

`PlayerInputSource` exposes immutable binding snapshots, its original defaults, an atomic import method, and binding change notifications. The persistence adapter decides where to store changes; the input class has no file access. Imported profiles cannot remove or alter fixed menu and aim controls. Root's phase 9 preview applies language/audio preferences and stores rebindings in its separate Unity profile; the complete menu conversion remains phase 24.

`settings-oracle.json` was recorded from **two fresh Godot 4.4.1 processes** using a verified random application/user-directory identity. Ten synthetic cases cover missing files, complete defaults, old shortcut conflicts, logical/physical keys and modifiers, explicit empty arrays, invalid arrays, oversized/duplicate arrays, unknown multiline fields, malformed files, and unsupported languages. The recorder calls the real `Controls._load_bindings`, `Lang.startup_locale`, `Sound._ready`, `GameState._load_meta`, and `GameState.load_meta`. Expected ConfigFile parse diagnostics are accepted only for the explicitly malformed fixtures; other engine/script errors fail recording. A source fingerprint proves the protected game files were unchanged.

The Unity native checks compare all ten cases against that frozen oracle, then exercise imported modifier bindings through the actual Input System event queue, binding persistence round trips/change notifications, fixed menu protection, immutable source bytes, inert script-shaped records, malformed text, and parser limits. The Python checks verify the exported source contract and exact runtime resource copy; they do not substitute for native execution.
